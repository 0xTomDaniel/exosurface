# Post-spike common statement — explicitly ratified

Date: 2026-09-13. This records a reviewer recommendation, not the operator's adoption of an architecture or production readiness.

1. **Direction.** Recommend A2UI over A2A with Pi as the initial single-protocol direction. Confidence in its ranking is low. Both reviewers now independently propose the same central scores after cross-examination: W1–W6 A2A = 2.5 / 3.5 / 3 / 4 / 2.5 / 3.5; AG-UI = 3 / 3.5 / 3 / 2.5 / 3 / 3.5. With weights 25 / 20 / 20 / 15 / 10 / 10 these are 3.125 and 3.075 out of 5. The 0.05 margin is within judgment uncertainty, not measured superiority. Reducing A2A W4 by 0.5 flips the order; raising AG-UI W5 by 0.5 ties it. Reviewer range estimates remain distinct in the record.

2. **Reasons and boundaries.** A2A provides useful standard work-control contracts, stock event-to-task accumulation/store-call sequencing, and published client methods. Get/List are exercised by SDK-client tests; the delivered browser uses native CancelTask but private thread discovery/checkpoints. Cancellation truthfulness is demonstrated only for the spike's tested executor/restart paths; it is not a universal SDK guarantee. Exo still owns execution, durable storage, recovery, access scoping, and truthful work termination. This useful reuse, together with the smaller-than-forecast AG-UI processing benefit, supports the initial direction qualitatively; the arithmetic alone does not justify it.

3. **AG-UI remains viable without SDK patches.** Its supported AbstractAgent run/connect/abort overrides, stock verifier, state application, subscribers, and detach behavior work in the demonstrated custom browser/Pi stack. This is material counterevidence to a blanket claim that AG-UI cannot connect to background agents without patching. It still requires Exo's transport and lifecycle support; it does not establish that stock HttpAgent or CopilotKit now supplies the complete desired behavior. The delivered UI renders history/utterances from Exo view.turns and applies raw A2UI activity operations; accumulated SDK messages are only counted diagnostically. W5 is 3, down from the forecast's 4. Switching the rendering array would not remove Exo's semantic archive, reference validation, or Pi-context ownership, so the proposed message-remap experiment was withdrawn.

4. **Costs shared versus different.** Background execution, source authority, meaningful Turn/Surface/Utterance history, exact references, Pi-context construction, retention, and admission safety belong to Exo on both paths. A2A additionally owns renewable observer Tasks, discovery, retention, readiness, heartbeat-assisted release, HTTP closure, and store reconciliation. AG-UI additionally owns its connect transport/observe endpoint and publication framing. These count as owned support, not SDK patches and not free protocol capabilities. The common semantic work is excluded from comparative translation costs. Fixed-schema versus model-authored A2UI is a generation-policy difference, not a W6 protocol penalty. W2 and W6 are tied.

5. **Evidence limitations are mandatory.** Both have bounded recorded background/restart/detach/browser/Pi evidence using unchanged SDKs. Neither passes production readiness. AG-UI demonstrably overwrote an arbitrary external edit during acceptance. A2A's exclusive new-file strategy avoids that overwrite path but leaves the final stale-acceptance window and later plan-file reconciliation unresolved. Local concurrent callers passing does not imply safety against arbitrary external writers. Both have source-inferred capacity/failure-atomicity hazards without saturation proof. A2A exercised an actual stalled-writer drop, but its healthy companion was an RPC, not an advancing observer. AG-UI recorded zero writer drops; its six-toggle browser assertion can pass at the initial value without proving final-revision catch-up. Neither forced the snapshot/subscription cut. Do not turn these unequal tests into protocol score advantages.

6. **Chatless qualification.** A2A's recorded Pi scenario asserts no person or Exo utterance. AG-UI proves visually initiated, mixed, and historical Pi interaction, but its current Pi Adapter requires nonempty model text; a fully utterance-free Pi exchange is unproved and conflicts with that Adapter policy. Its wire/publication path can carry utterance-free turns. This is an implementation gap, not an AG-UI protocol prohibition or a change to Exosurface's chat-optional requirement.

7. **Next action and reversal condition.** No additional broad comparative spike is required before an initial direction. A matched observer-fault probe is the first mandatory lifecycle verification on the selected implementation: a paused and a continuously advancing observer, forced snapshot cuts/renewals, actual backpressure, interrupted publication, bounded release, and an asserted unique final revision. A2A needing an SDK patch/private queue repair to satisfy that contract while AG-UI passes via supported extension points would reverse the recommendation. Ordinary host bugs must be repaired and do not automatically select the other protocol. Source-write concurrency and capacity failure-atomicity must also be resolved before reliance. Latest stable registry versions checked by the moderator match the spike pins (A2A JS 1.1.0; AG-UI client 0.0.59), so no newer-version upgrade dry run was available; maintenance scores stay uncertain.

8. **No combined topology yet.** Neither spike demonstrates a present benefit sufficient to justify A2UI over AG-UI over A2A, or two browser protocol integrations. Keep composition as an open question with an explicit saving required. The two packages remain independent, unmodified by this debate. Auditors read source and recorded evidence; this debate did not rerun tests or model calls.
