# Weighted comparison: A2UI over A2A versus A2UI over AG-UI

Post-spike assessment, September 13, 2026. All six criteria have provisional scores, plausible ranges and explicit reasoning. The weights remain proposed priorities. This version incorporates the [independent spikes and ratified Astra/Fable review](research/2026-09-13-spike-debate.md); the [earlier forecast](research/2026-09-13-weighted-forecast.md) remains a historical record. Scores judge integration burden, not measured hours or reliability.

**Current reviewer recommendation: A2UI over A2A, narrowly and reversibly.** Both reviewers agreed on **A2A 3.125/5 versus AG-UI 3.075/5**, displayed as **3.13 versus 3.08**, with **100% of the weight scored**. The 0.05 margin is within judgment uncertainty. Useful standard work controls and less AG-UI processing reuse than forecast support this initial direction qualitatively; decimal arithmetic does not establish superiority. No final architecture is selected. **Follow-up: W4's net value is under review.** The [private control-convention audit](research/2026-09-13-private-control-convention.md) finds that both browsers already use Exo work projections; AG-UI does not need an A2A-shaped query system for that bounded view. Preserve the ratified scores below as the last agreed assessment, not a measurement of saved client work.

**Background-support evidence:** Both spikes demonstrated bounded browser/background behavior with unchanged published SDKs and substantial owned support. AG-UI uses supported run/connect/abort overrides, official verification, state application and subscribers. Its default protected connect method is unimplemented; the public connectAgent wrapper catches the specific error and returns an empty result. Successful return is not observation. A2A uses a close-aware route and renewable observer Tasks, including heartbeat-assisted cleanup. Neither stock default stack supplies the complete Exo lifecycle. W1 and W3 explicitly charge this support.

**Next verification:** No additional broad comparative spike is required before an initial direction. The selected implementation needs a matched observer-fault probe, source-write safety and failure-atomic capacity handling before reliance. A combined topology has no demonstrated saving yet. These scores compare only the independent single-protocol paths.

Published versions in the spikes are A2A JS 1.1.0, AG-UI client/core 0.0.59, Pi 0.85.1 and A2UI/Lit 0.11.0 using v0.9/basic catalog. The debate audited recorded execution and source; it did not rerun tests or model calls. AG-UI's metadata propagation correction remains valid, but available processing earns credit only where the delivered client uses it.

## Exo's private control convention: the assumption under review

The AG-UI browser sends an Exo cancel command with a requestId and workId through the existing runAgent/forwardedProps path. A running job returns **cancelling**; the observer later reports **cancelled** or another terminal outcome. The same snapshot already contains the current work list. Plan, select, accept, lights and history remain Exo product semantics under A2A too. This is a small additional control Interface, with real behavioral obligations; it is not a requirement to reproduce A2A's query family.

**Command receipt, current work and source effect are separate facts.** A retried admission can return its original accepted receipt after restart while the work snapshot says interrupted. That case is asserted by an existing AG-UI test. Exo must preserve correlation and tell clients which result is historical acknowledgement and which is current truth. Both candidates need this product contract; transport completion alone is insufficient.

**Concrete unfinished work:** AG-UI uses generic result objects and a Stop button that does not handle its acknowledgement/errors. The A2A Stop button also lacks full outcome/error presentation. A2A's owned store uses ID ordering and numeric-offset page tokens where the pinned standard specifies time ordering and cursor pagination; its page-count test does not validate those semantics. These are source-audit findings, not newly executed failures or SDK repair requirements.

**Open design:** A small Exo client Module could centralize typed intent receipts, cancellation outcomes, exact historical lookup and the existing thread observation. It can sit over either candidate while preserving the selected SDK. Judge how much maintained behavior disappears for real callers, including retry and failure cases. The [detailed audit and proposed bounded comparison](research/2026-09-13-private-control-convention.md) strengthen the case for AG-UI's small private convention without establishing a new winner. No new Astra/Fable consensus is implied, and all background/source gates remain mandatory.

## Calculation and limits

**Weighted average = sum of (weight percentage × score) / 100.** A2A: (25×2.5 + 20×3.5 + 20×3 + 15×4 + 10×2.5 + 10×3.5) / 100 = **3.125**. AG-UI: (25×3 + 20×3.5 + 20×3 + 15×2.5 + 10×3 + 10×3.5) / 100 = **3.075**.

| Quantity | A2UI over A2A | A2UI over AG-UI | Interpretation |
| --- | --- | --- | --- |
| Weighted sum before division by 100 | 312.5 | 307.5 | Every criterion contributes; no missing-weight renormalization. |
| Weighted average, displayed to two decimals | **3.13/5** | **3.08/5** | A2A leads by 0.05/5 on unrounded judgments. Arithmetic precision does not measure an engineering advantage. |
| Scoring coverage | **100%** | **100%** | All six costs have estimates. This is not evidence that 100% of requirements pass. |
| Complete mandatory requirements | **Incomplete; unresolved gates** | **Incomplete; G4 failure plus unresolved gates** | Neither implementation can be adopted unchanged. Shared host defects do not become protocol score penalties, and scores do not excuse defects. |

**Interpretation of the ratified scores:** The candidates are effectively even. Standard work contracts narrowly tipped that assessment toward A2A; their net saving for the actual owned clients is now under review. W2, W3 and W6 remain tied. The table records the last agreed judgment, not measured total cost, reliability, probability of success or production readiness.

Equal score steps are a planning approximation. Confidence does not multiply scores, and range endpoints are not independently combined into a statistical interval. Related initial and recurring risks can move together; joint scenarios below make that visible.

External-agent interoperability has no concrete v1 consumer and receives no speculative bonus. The composition question remains open because work controls and client processing can be complementary. However, the spikes did not demonstrate a present saving sufficient to justify another protocol layer; accumulated AG-UI messages did no delivered rendering work.

There are three distinct arrangements: a browser using both protocols; an AG-UI-to-A2A host bridge; or sibling A2A and AG-UI Adapters over one Exo/Pi core. The third shares thread/history, receipts, work, context and ordered publication without serial protocol translation. A client can speak only one protocol. Sharing a Pi factory alone would not remove duplicated domain behavior.

The [A2UI input and shared-core audit](research/2026-09-13-a2ui-input-and-shared-core.md) traces structured actions through both protocols into explicit Pi context. It records A2A action-provenance loss and distinguishes the actual AG-UI input route from optional middleware. These implementation differences do not establish protocol superiority or change W2/W6 scores.

The primary-agent preference is to explore the shared core if both protocols have useful callers. Each enabled Adapter still owns its lifecycle mapping, resource handling and conformance; AG-UI does not inherit native task controls merely because A2A is available alongside it. A2A's work controls alone do not justify two protocols until the cost of the smaller Exo convention is understood. No combined topology is selected or scored, and single-protocol scores cannot be added to rate one.
